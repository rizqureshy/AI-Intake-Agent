# BRD / ROI Output Template

Once enough information is captured (see the [completeness check](routing-logic.md#completeness-check)),
the agent generates a presentable **Business Requirements and ROI Document** using the structure
below. Mark all ROI values as **estimates** unless validated.

---

# Business Requirements and ROI Document

## 1. Executive Summary
Briefly summarize the request, business problem, intended outcome, and expected value.

## 2. Project Overview
Describe the project, request type, impacted organization, and process area.

## 3. Business Context
Explain why this request exists and what triggered it.

## 4. Problem Statement
Clearly describe the business problem being solved. (Not the proposed solution.)

## 5. Current State
Explain how the process works today, including current systems, tools, teams, and pain points.

## 6. Impacted Users and Teams
List the users, teams, organizations, or regions affected.

## 7. Process Owner and SME
Identify the current process owner, system owner, SME, and key stakeholders.

## 8. Desired Future State
Describe the improved experience, process, or capability.

## 9. Scope
Describe what is included in the request.

## 10. Out of Scope
Describe what is not included or should be considered later.

## 11. Business Requirements
List clear business requirements using this format:

> "As a [persona], I need [capability], so that [business value]."

## 12. Functional Requirements
List the capabilities the solution should provide.

## 13. Non-Functional Requirements
Include security, privacy, compliance, auditability, performance, access, data retention, and
reporting needs where relevant.

## 14. Systems, Technologies, and Data Sources
List current and expected systems, tools, documents, repositories, data sources, or
integrations.

## 15. ROI and Business Value
Summarize expected value — time savings, revenue impact, cost savings, risk reduction, or
strategic value. **All values marked as estimates unless validated.**

## 16. KPIs and Success Metrics
Recommend how success should be measured. Examples: hours saved · cycle time reduction ·
adoption rate · error reduction · user satisfaction · revenue influenced · cost reduction ·
risk reduction · compliance improvement.

## 17. Risks, Assumptions, and Dependencies
List known risks, assumptions, dependencies, data issues, process risks, and change management
considerations.

## 18. Sponsor Information
List the VP sponsor and approval status.

## 19. Readiness Assessment
Classify the request as one of:
- Ready for VP review
- Needs more information
- Needs SME validation
- Needs ROI validation
- Not ready for formal review

## 20. Recommended Routing
Recommend where the request should go after sponsor approval. Options:
- Core DIO / Technology Delivery
- AI Innovation
- Data and Analytics
- Functional Team / Alternative Delivery
- Process Improvement
- Existing Tool / Configuration Change
- Not ready for routing

## 21. Next Step
State the next step clearly. Examples:
- Send to VP sponsor for review
- Return to requester for more information
- Send to SME for validation
- Route to intake review team after sponsor approval
- Save as draft
